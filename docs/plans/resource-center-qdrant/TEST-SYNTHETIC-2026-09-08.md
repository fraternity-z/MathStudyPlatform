# P5 原创合成语料与检索链路验证

## 结论

按项目负责人“没有真实语料，你直接自己编写测试即可”的指令，自行编写数学材料和查询标注，完成真实 PostgreSQL、正式 HTTP/检索/引用应用链路与 Mock 向量依赖的集成验证。125 个冻结检索场景、288 次引用校验、授权撤销与竞态、152 个切块场景、26 个公开接口边界场景及 250 次并发检索通过，`go test -race` 通过。

精确术语检索通过不等于自然问句质量通过：24 条独立中文改写问句的 FTS Recall@5 为 0/24，字符二元组 Mock 混合检索为 20/24。此结果保留为 P5 调优基线；不以 Mock 得分宣称真实 embedding 或教学效果达标，M5 保持未通过。

## 数据与环境

| 项目 | 本次设置 |
|---|---|
| 语料 | 24 篇原创短讲义，正文及英文术语共 3624 UTF-8 字节；每篇一个正文 chunk |
| 学科 | 数列 2、代数 4、微积分 6、平面几何 4、概率 4、线性代数 4 |
| 表达 | 中文解释、公式/数值例子和英文术语，包含易混淆概念；没有学生或第三方受保护数据 |
| 标注 | 每篇预先指定中文术语、英文术语及一条自然改写问句；相关资源按材料主题确定，不从搜索结果反推 |
| 权限 | 一个材料所有者和一个无知识库授权的账号；另有 deny、停用、撤回、代际错误和撤权竞态 |
| 数据库 | 独立 loopback PostgreSQL 18 测试实例；从空库应用全部 22 个正式迁移 |
| API | 正式 resource HTTP handler、SearchService、VectorRetriever、PostgreSQL Repository；本地 HTTPS 证书校验与 `no-store` |
| Mock 边界 | 账号 token 解码、embedding 和向量存储。Mock embedding 为 256 维字符二元组哈希归一化；向量检索按点积排序并执行资源白名单过滤，不含查询→答案查表 |
| 未调用 | 管理员真实 embedding/rerank/Tutor 模型、外部 provider、真实 Qdrant 引擎；没有模型激活或实际费用 |
| 数据准备 | 资源通过正式资源 service 创建；测试直接准备文档版本、chunk 与 manifest，因此本轮不是异步上传/解析/worker 全链路复测 |

Docker 引擎未能在本轮启动，已结束启动等待；使用独立原生 PostgreSQL 完成真实 SQL 验证，没有把 Mock 向量存储写成真实 Qdrant 实机证据。

## 检索与引用结果

| 场景 | 样本 | 结果 |
|---|---:|---|
| 中文/英文精确术语，Mock hybrid | 48 | Recall@5 / MRR@5 / nDCG@5 均为 1.0 |
| 同一精确术语，FTS-only | 48 | 三项排名指标均为 1.0；符合预期降级模式 |
| 无关查询，FTS-only | 5 | 均返回空主结果与空邻接结果 |
| 无权限账号搜索 | 24 | 均无资源返回 |
| 正式引用再次解析 | 288 | 知识库、版本、generation、引用身份、正文及 hash 全部匹配 |
| 中文自然改写，FTS-only | 24 | Recall@5 = 0.0，质量待优化 |
| 中文自然改写，Mock hybrid | 24 | Recall@5 = 0.8333；仅作为 Mock 行为观察 |
| 无关查询，Mock hybrid | 1 | 返回 5 个有权访问的无关候选；没有生成 Tutor 答案 |

125 个冻结场景由前四行组成；后续改写及无关向量查询单独观察，未混入精确术语的通过分数。无答案的通过结果仅适用于 FTS 空结果；向量近邻存在并不意味着能回答问题，Tutor 面对无关候选的行为须另验。

授权专项包括无权限直接读引用、所有者正常引用、添加 deny 后旧引用拒绝、撤权后搜索为空、错误 generation、账号停用、资源撤回。另在第一次 SQL 鉴权成功之后立即写入 deny，第二次最终鉴权返回空结果，未泄露之前读取的正文。状态复原后继续验证读取。

公开接口边界覆盖空/过长/含控制字符的 query、非法 TopK/超时/类型/用户、取消、上下文预算不足、未知知识库、scope/identity/授权失败、双路失败与单独 FTS 失败、非法引用、资源数量限制、非法维度、embedding 出错/维度不符/全零向量及空依赖，共 26 个场景；外部错误内容不进入返回值。

## 切块与小型并发验证

将每篇正文重复 30 次，仅用于生成边界压力，使用正式 DeterministicChunker 对 3 个字节预算 × 2 个 overlap 设置 × 24 个文档验证确定性、UTF-8、预算、原文偏移和标题父子关系；再验证非法策略、非法文本/页码及取消，共 152 个场景。

| MaxTokens（UTF-8 字节上界估计） | overlap | 24 个压力文档总 chunk 数 |
|---:|---:|---:|
| 128 | 0 | 972 |
| 128 | 32 | 1346 |
| 512 | 0 | 232 |
| 512 | 128 | 297 |
| 2048 | 0 | 83 |
| 2048 | 512 | 91 |

这组结果证明边界正确并记录切块数量成本，不用于断言哪种切块策略的真实 Recall 更高；没有修改默认参数。

在 24 篇/24 个向量 fixture 上运行 5 并发 × 50 请求，250 次读取无错误和非预期降级；最终带 race instrumentation 的本地运行 P95 为 73.895 ms，约 118.74 QPS。125 次顺序 HTTPS 评估搜索 P50/P95/P99 为 33.03/68.72/79.35 ms。样本小、已有缓存、Mock 向量依赖且未进行 soak，均不用于放行 10 万/百万容量门槛。


命令在 `backend` 执行；临时用例包含 8 个子测试，全部通过。重点函数语句覆盖率：Chunk 92.6%、Search 86.0%、RetrieveCandidates 82.5%、SearchLexical 84.2%、AuthorizeSearchChunks 82.4%。所选两个大包整体覆盖率为 6.2%，覆盖本次路径之外的大量业务，不把重点函数覆盖率写成全仓覆盖率。此前评估器 Python Mock 的 99% 可执行行覆盖仍是独立证据。

后续可继续使用自行编写的合成材料，不再以缺少真实教学语料作为工具与功能测试的阻断。优先处理中文改写的词法召回与负例策略，再按已批准边界做真实向量引擎、模型质量、目标容量、混合负载和 soak；合成样本扩展到更多长度和格式后再决定参数，不用本次精确词条结果提前关闭 P5/M5。
