## 环境与冻结数据

- 独立 Linux 容器，固定 `qdrant/qdrant:v1.14.1`，2 CPU、2 GiB 容器内存上限；Docker 引擎 29.7.2，WSL 总内存约 3.83 GiB。
- 测试实例仅映射 loopback 独立端口；业务 `msp_qdrant` 不参与实验。每组使用独立随机名称 collection，结束后删除。
- 稠密数据为 1024 维、64 个高维聚簇：Go `math/rand`、中心种子 20260908，中心每维正态随机量除以 sqrt(1024)；点 id 从 0 开始，以 id%64 选择中心，用种子 id+94217 加入标准差 0.10/sqrt(1024) 的噪声。
- 每档各 100 条查询，查询 id=count+5000+i，噪声标准差改为 0.14/sqrt(1024)。查询不从返回结果反推。两种容量档的查询编号不同，不伪称逐条相同问题的扩容回归。
- payload 为 tenant_id=id%4、topic=id%64；查询限定同一个 tenant_id，选择性 25%。这是向量层过滤测试，不代替 PostgreSQL ACL 或完整多租户验收。
- 稠密原始 float32 按点、维度顺序以 little-endian 4 字节编码计算 SHA-256。一万条：`e84b92fb278c9830ed3f141f18c0791bf0c1b0e2dbb08fa5937ef467a66d2d53`；十万条：`6de9f45a2450f87b1d048401cbc4be5e5d12b68135cd4506793a613478c60ec5`。
- 稀疏数据单独生成，每点三个非零坐标 `[id%64,64+id%997,2048+id%101]`，值为 `[1,0.2,0.1]`，坐标空间 2149。十万条摘要按交替坐标/值转 float32 little-endian 编码：`abfb5266a0bf2c976bee59e91fab79a8b05c86ec38ddeac8cd6546dac91f22da`。不把稀疏耗时和稠密语义质量直接等同。

## 实验参数与判定

HNSW 固定 m=16、ef_construct=100、max_indexing_threads=2、full_scan_threshold=1000 KiB。先以 indexing_threshold=0 批量上传，每批 256 点且 wait=true；再设置 indexing_threshold=1000 KiB，等待 green、optimizer_status=ok 和至少 95% 向量已索引。默认目标 segment 数为 2，实际 segment 数见结果。所有稠密组最终索引数均等于输入点数。

普通检索使用 hnsw_ef=128、TopK=10，量化开启 rescore 与 oversampling=2。精确 oracle 从第一组以 exact=true、quantization.ignore=true 生成，后续同容量稠密组与同一 oracle 对比。每组五并发、100 次测量；HNSW 基线预先要求 Recall@10>=0.90、P95<=1 秒。其余组是对照实验，子测试 PASS 只说明请求/过滤/适配器契约完成，不表示质量达到发布门槛。

稀疏组另用独立 Go 数值 oracle：遍历指定租户的全部合成点，按匹配坐标计算点积并检查最高十个分数（允许同分不同 ID）。十万条的数值 oracle 通过。

Docker 启动故障通过保留性备份仅含零字节 socket 的运行目录恢复，备份留在原 Docker 本地目录旁。自动审批仍拒绝清理 `.tmp/vector-goal-pg`、空 `.tmp/vector-goal-qdrant` 以及旧日志/覆盖产物，明确授权后复试仍只返回策略阻止；这些忽略目录残留没有暂存，不将清理写成全部完成。

生产参数保持现状，本轮只交付已验证的中文词法修复（`88695f9`）和实验记录。P5 仍欠更广数据分布、HNSW/融合校准、真实模型与 rerank/Tutor 质量、混合入库/重建/soak、完整副本/缓存/冷恢复对照及参数发布回滚。按用户指令，本轮不继续这些事项，也不进入 P6。
