# 学生学习反馈评估 2026年10月16日

## 结论

学生画像、针对性出题、正式判题、错因诊断、提示辅助记录和复习计划已经形成可运行的闭环。本次使用自行生成的教学数据与真实模型，完成了 API、数据库和浏览器验证。

**当前主要缺口是学习证据的可信度和一致性。**同题重复提交可把 DKT 掌握度推至 99.9%，但学习反馈仍认定只有一道有效新题；任意上报的学习时长会污染本人及班级比较；题目详情提供的提示没有进入辅助证据；选项答对时不会检查学生明确写错的过程。因此，平台可以辅助安排练习，但现有掌握度、优势标签和学习时长不适合直接作为教学达标或学生评价依据。

本次只做评估和记录，未修改产品实现。当前行动项已进入 [项目待办](../../TODO.md)，下文保留复现依据及建议验收标准。合成数据验证不证明真实学生的学习增益。

## 需要优先处理的问题

### 1 同题重复提交抬高掌握度和优势标签

**复现：**无历史学生开始画像行动，对同一道课程题连续答对 10 次；每次使用新的合法 `submission_id`，不携带错题重做参数。

**实测：**10 次都按权重 1 更新。掌握度依次为 `0.6515 → 0.8006 → 0.9217 → 0.999`，第 4 次达到 99.9%。画像将该概念列为优势、超过班级 100% 的有效比较样本，行动完成 10/10；同时反馈仍显示 `independent_attempts=1`、`stage=diagnostic`。

这不是同一请求重复记账：相同提交 ID 的幂等正常。缺口是普通提交与显式重做的学习权重规则不一致。前端“题量已完成”措辞能避免把完成直接说成掌握，但不能消除 DKT 和优势标签的失真。

**定位：**`backend/internal/application/exercise/service.go:1681` 的 `submissionMasteryWeight` 对普通请求默认全权重；同文件 `2520` 附近更新 DKT 并累计每次作答。反馈层的首答/题面去重没有约束这条更新路径。

**建议和验收：**在服务端统一识别同学生、同题或同题型的既有暴露，区分首次测量、练习重做和到期复习，不依赖客户端主动声明重做。保留实际练习次数，但单独展示有效新题数。重复同题不应提高独立验证数量，也不应仅凭短时重做进入高可信优势；相同提交 ID 重放、换 ID 重做、显式错题重做都应进入一致的证据政策。具体权重需校准，简单把 1 改为 0.35 仍可能在大量重复后饱和。

### 2 学习时长接受负数和不合理大值

**复现：**向 `/api/v1/exercise/submit` 分别提交 `time_spent_seconds=-60` 和 `604800`，其余字段均合法。

**实测：**两次均返回 200，数据库原值保存。加上此前 60 秒的正常作答，该学生的画像累计为 10080 分钟；短时间内上报的一周时长进入班级比较，其他学生页面中的同学平均时长也被拉高。

**定位：**`backend/internal/adapter/http/exercise/handler.go:153` 接收整数；`backend/internal/application/exercise/service.go:1255` 直接写入；`backend/internal/adapter/postgres/progress_repository.go:381` 等查询直接聚合。

**建议和验收：**拒绝负值、溢出和明显超界值；用服务端题目开始时间或有界会话记录校验有效时长，并明确切后台与多端并行规则。异常样本不得进入画像、排名或班级均值。验收覆盖负数、零、上界、跨天、重复上报及并发累计；上线前评估历史异常记录的清理政策。

### 3 题目详情提供的提示未进入辅助证据

**复现：**生成填空题后，提交前读取 `/api/v1/exercise/{id}`；响应包含“将函数看作外层幂函数与内层函数的复合，求导时注意乘以内层函数的导数”。随后按正确表达式提交。

**实测：**题目提示已通过 API 可取得，但该学生没有 `exercise_hint_evidence` 记录，提交仍标为 `no_recorded_hint`、权重 1，并计入有效首答。通过正式 Tutor 请求提示则会记录并降至 0.35。

**定位：**`backend/internal/application/exercise/service.go:1966` 在题目详情直接返回 `meta.hints`。本次证实的是 API 提示交付路径；没有把前端普通加载等同于学生已经阅读提示。

**建议和验收：**普通题目详情不要预先下发提示正文，显式提示入口统一走最小证据记录与交付流程。所有实际提供题目帮助的入口采用同一辅助口径，首次交付、重放、并发提交和交付失败都应有确定结果，避免为了记证据而把所有普通加载都判为求助。

### 4 正确选项掩盖错误推理过程

**复现：**题目为 `y=(2x+1)^2` 求导，选择正确项 A，同时提交步骤：“平方函数求导不需要乘内层导数，所以结果应为2(2x+1)，我随便选A。”

**实测：**返回 `score=1`、`diagnosis=null`、`mastery_weight=1`，掌握度更新至 0.6515；错误过程完整保存在数据库，但未影响学习反馈。

**定位：**`backend/internal/application/exercise/service.go:1063` 仅在最终答案错误时调用诊断。`choice_exact` 的置信度 1 表示选项匹配确定，不能解释为概念掌握确定。

**性质：**正确选项的得分符合当前判题契约；问题是缺少过程评价，影响画像证据，而非选择题判分算错。此项与已有关键步骤评价待办一致，本次增加了明确复现。

**建议和验收：**分开保存结果正确性、关键步骤正确性和推理证据是否充足；答案与步骤冲突时提示检查过程，降低该记录作为掌握证据的强度。对缺少步骤的选择题保留正常练习体验，不将未写步骤直接判错。验收至少包括答对但步骤错、答错但核心方法对、缺步骤、符号等价和无法判断。

## 真实模型质量样本

| 用途 | 实际题目或表现 | 结果 |
| --- | --- | --- |
| 错因修复 | `f(x)=sin(x²+1)` 求导，干扰项含漏乘内层导数 | 正解 `2x cos(x²+1)`；故意选错后定位 `procedural / missing_inner_derivative`，指向遗漏的内层求导步骤 |
| 迁移 | 给定 `f(ln2)=ln3`、`f′(ln2)=4`，求 `g(x)=exp(f(ln(1+x²)))` 的 `g′(1)` | 正解 12；相较历史平方复合题增加指数、对数嵌套和给定点信息 |
| 冷启动填空 | `f(x)=(3x²+1)^4` 求导 | 正解 `24x(3x²+1)^3`；正确提交与追踪成功 |
| 撤去提示后验证 | `y=sin(x²)` 求导 | 正解 `2x cos(x²)`；正式 Tutor 只作分步引导，提示后提交按辅助处理 |
| 浏览器行动生成 | `f(x)=ln(1+e^x)` 求导 | 正解 `e^x/(1+e^x)`；选择、判题、解析和画像更新完成 |

上述题目均经过现有生成及独立求解复核路径，人工核对数学结果未发现错误。4 个有完整 API 计时的生成样本为 **22.2–36.5 秒**；两份画像生成分别约 **17.6 秒、37.1 秒**，一次错因诊断约 **6.7 秒**，提示完整返回约 **7.0 秒**。这些是单次样本，不是生产 P95 或成功率估计。

两份画像分别针对冷启动和连续错误。冷启动报告没有臆测学习态度；错因报告正确区分累计 DKT、当前范围统计、近 30 天首答和置信度，给出标注内外层、换新题与间隔检验的步骤。报告生成后新增作答不会改写旧报告，界面显示报告范围、数据截止和生成时间；建议进一步显示“此后有多少次新作答”，帮助学生理解新统计与旧报告的差别。

嵌入测试使用 8 段原创教学片段与 6 条中文错因查询，真实返回的向量均为有限值。余弦排序 **Top 1 命中 5/6，Top 3 命中 6/6**。“遇到极限能不能直接上下分别求导”把换元积分排在洛必达法则前，分数分别为 0.5187 和 0.5146。建议增加概念别名、规则适用条件和相近错因的标注样本，再比较混合检索或重排；该结果不能作为已接通 Qdrant 或全库 RAG 质量的证据。

| 能力 | 当前判断 | 最需要补充的证据 |

| 针对性生成 | 能读取错因、首答及间隔状态，难度和题型会变化 | 更广知识点与题型；语义重复识别；受控迁移标签；教师复核 |
