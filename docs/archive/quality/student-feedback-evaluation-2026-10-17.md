# 学生学习反馈评估 2026年10月17日

## 结论

当前版本已经能跑通“画像建议 → 针对性出题 → 作答反馈 → 学习记录更新”的主流程，重复提交、异常时长、AI 题目提示降权及过程错误的掌握度保护都有实测证据。**学习反馈闭环仍不完整，建议先处理下列三个 P1 问题，再扩大教学试用：**

1. 班级题通过通用辅导获得提示后，仍按未记录提示的独立作答计分。
2. 答案正确但过程错误的记录虽然被识别并降权，却没有进入该学生的概念画像、错题和复习任务。
3. 标准选择题页面没有解题步骤入口，后端已有的过程评价能力尚未接入主要学生流程。

另有三个 P2 问题：同义改写题重复增加掌握度、生成可靠性与等待时间不足、掌握度“趋势”没有使用历史值。这里的 P1 表示直接影响学习反馈可信度或核心功能可达性；P2 表示需随后修复的准确性或体验问题。

本次是功能与证据一致性评估。合成历史数据用于覆盖状态，不能据此证明 DKT 概率经过校准，也不能证明学生的真实长期学习收益。

## 优先处理的问题

### P1-1 班级题辅导提示没有进入辅助证据

**复现：** 通过班级题实际使用的 `/session/start-chat` 合同，对 `f(x)=(2x+1)^2` 请求解题切入点。模型明确给出内外层拆分和链式求导提示。随后提交正确选项。

**实际：** 提示证据数为0，提交返回 `assistance_status=no_recorded_hint`、`evidence_kind=first_attempt`、`mastery_weight=1`，首次掌握度增加至0.6465。作为对照，同一学生在 AI 生成题使用绑定辅导接口，真实收到提示后返回 `hinted`、权重0.35，证据数为1。

**原因与影响：** 班级题按钮跳到通用会话，题目ID只出现在消息文本中，没有接上专用提示证据写入链路。学生得到实质性帮助后仍被当作独立完成，画像和推荐都会受影响。`/session/exercise-tutor` 对班级题返回404符合当前“仅 AI 题”的实现限制，404本身不是本条缺陷。

定位：[ExercisePage.tsx](../../../frontend/src/pages/student/ExercisePage.tsx)、[tutorContext.ts](../../../frontend/src/modules/exercise/tutorContext.ts)、[SessionChatPage](../../../frontend/src/pages/student/SessionChatPage/index.tsx)、[exercise/tutor.go](../../../backend/internal/application/exercise/tutor.go)。

**优化与验收：** 为各题目来源使用服务端校验的题目/会话绑定，在首次实际输出非空提示前可靠记录辅助证据。不能依赖解析聊天文本中的题目ID。覆盖班级题、AI题及后续接入的其他题源，验证重放、并发和提交后的证据冻结；仅打开空会话不应被当作已获得帮助。

证据：[class-hint-observation.json](../../../output/student-feedback-audit-1017/class-hint-observation.json)、[followup-evidence.json](../../../output/student-feedback-audit-1017/followup-evidence.json)。

### P1-2 过程错误被识别，却没有进入概念画像和复习

**复现：** 一个无历史数据的学生提交正确选项A，同时填写：“平方函数求导不需要乘内层导数，因此 f'(0)=2，我随便选A。”

**实际：** 后端判断结果正确、过程错误，诊断为 `procedural/procedure_misuse`，过程置信度0.99，掌握权重0，未增加 DKT。随后画像的优势、待改进和观察列表均为空，只给出不绑定概念的“开始诊断练习”；错题总数0、活跃复习任务0。直接读取同一份学习证据构建反馈，却能够得到 `repair` 阶段和正确的过程错因。

**原因与影响：** 画像选取概念依赖已有 DKT 状态/行动，权重0的首次作答没有创建该状态，概念因而漏选；错题及新复习任务仍主要依据最终答案是否错误。系统已经知道学生存在错误推理，却没有安排针对性纠正。

定位：[exercise/service.go](../../../backend/internal/application/exercise/service.go) 的零权重处理、[progress/portrait_insights.go](../../../backend/internal/application/progress/portrait_insights.go) 的候选概念、[portrait/service.go](../../../backend/internal/application/portrait/service.go) 的概念范围、[exercise/mistake_review.go](../../../backend/internal/application/exercise/mistake_review.go)、[mistake_repository.go](../../../backend/internal/adapter/postgres/mistake_repository.go)。

**优化与验收：** 从近期作答/诊断补充画像概念，允许零掌握权重但有明确错误证据的概念进入干预。保留最终答案得分，同时将“过程错误”作为独立的纠错/复习依据；模型不确定不能直接等同于过程错误。验收该样本在提交后立即出现对应概念、错因及可执行行动，完成纠正后再以新题和延迟验证确认改善。

证据：[http-evidence.json](../../../output/student-feedback-audit-1017/http-evidence.json) 中 `live-steps-process`、`steps-portrait-process`、`steps-mistakes-process`、`steps-tasks-process`；[steps-direct-feedback-process.json](../../../output/student-feedback-audit-1017/steps-direct-feedback-process.json)。最终进度查询仍复现这一遗漏。

### P1-3 学生选择题页面没有解题步骤入口

**复现：** 在真实浏览器中由画像行动进入 AI 选择题，完成选择并提交。题目为 `y=(x²+1)^4`，求 `y'(1)`，选择64后提交成功。

**实际：** 主要作答区域没有步骤输入控件；抓取的提交体只有题目ID、提交ID、答案和时长，没有 `answer_steps`。服务接口类型及序列化已支持该字段，但主要页面的提交调用未传入步骤。

**影响：** 本次通过 HTTP 直接提交才能覆盖的过程诊断，对标准选择题用户尚不可用。不能仅以服务接口支持步骤评价，就认定学生学习反馈功能已经完整。

定位：[exerciseViewModel.ts](../../../frontend/src/modules/exercise/hooks/exerciseViewModel.ts) 提交组装、[exerciseService.ts](../../../frontend/src/modules/exercise/services/exerciseService.ts) 的 `answerSteps`/`answer_steps`。

**优化与验收：** 加入可选的关键步骤输入及错误定位展示，将答案结果和过程评价分别呈现；不填写步骤应保持“未提供”，不能自动判为错误。验证输入保留、提交重试、移动端可用性，并通过真实 UI 复现 P1-2 的样本。

证据：[桌面练习截图](../../../output/playwright/audit1017-exercise-desktop.png)、[浏览器观测记录](../../../output/student-feedback-audit-1017/browser-observation.json)；浏览器实测请求体无 `answer_steps`，代码检索与之相符。

### P2-1 同义改写仍可重复计证据，掌握度与路径状态过于乐观

**复现：** 将同一个求导问题分别写为“设 f(x)…求 f'(0)”“已知函数…计算 x=0 处导数”“求 y=…在 x=0 的导数”“函数 g(t)…求 g'(0)”，数学结构、数值和答案完全相同，仅更换表述/变量名，并赋予不同题目ID。学生连续答对4次。

**实际：** 4次均按权重1计入，数据库掌握度0.999、置信度0.6302、独立作答数4。最终查询经过时间衰减后的掌握度约0.9985，学习路径仍标为 `completed`；画像阶段却继续要求新题及至少24小时后的验证。

**影响：** 精确文本去重有效，但不能阻止同义题增加掌握度。路径的“完成”又容易被理解为已经掌握，与画像证据要求不一致。

定位：[exercise_evidence.go](../../../backend/internal/adapter/postgres/exercise_evidence.go) 的 `learning_question_body_v1` 规范化文本匹配及路径完成判定。

**优化与验收：** 优先记录生成模板/题目变体关系，补充数学结构等价判定；向量检索可用于候选召回，不能独自决定两题等价。区分同一概念下的真正新题和只改措辞的同题。让学习路径与画像共享最低证据量、题目多样性和延迟验证要求，分别展示“当前正确率/估计掌握度/验证状态”。验收上述4题不再作为4份独立掌握证据，而实质不同的新题仍可贡献。

证据：[attempt-evidence.json](../../../output/student-feedback-audit-1017/attempt-evidence.json)、[final-dkt-evidence.json](../../../output/student-feedback-audit-1017/final-dkt-evidence.json)、[final-progress-evidence.json](../../../output/student-feedback-audit-1017/final-progress-evidence.json)。

### P2-2 生成失败可复现，模型链路等待时间偏长

初始5个生成场景成功4个。换元积分、难度0.65的选择题第一次约35.7秒后返回502，重试约32.2秒后仍返回 `MATH_SOLVER_INVALID_RESPONSE`。该学生生成题数量前后均0，没有保存未通过的题目，这项失败保护有效。

成功生成样本等待约26.9–76.8秒；3份画像报告约19.6–27.9秒；“我选择A。”这一缺少推导的过程样本等待约100.1秒，最终降级为 `indeterminate/process_unavailable`，权重0。该样本说明服务降级较保守，不能算作模型成功识别了“步骤不足”。

**优化与验收：** 将生成、结构解析、数学校验、超时分别计量，记录脱敏的失败阶段和错误码；对可恢复的结构问题做有上限的修复重试，保留数学校验。界面应明确进度、可重试状态和取消行为。随后固定场景做多轮成功率及 P50/P95 测量，再设定教学场景可接受的等待时间。本次样本不足以估计生产成功率，现有证据也不足以把502唯一归因于模型或业务实现。

证据：[generation-retry-observation.json](../../../output/student-feedback-audit-1017/generation-retry-observation.json)、[runtime.log](../../../output/student-feedback-audit-1017/runtime.log)、[followup.log](../../../output/student-feedback-audit-1017/followup.log)。

### P2-3 错题掌握度“趋势”使用当前水平，缺少真实历史比较

**实际：** 复习后的错题返回 `current=0.7947`、`previous=0.7947`，同时 `trend=improving`。实现将 previous 和 current 都赋为当前平均掌握度，并按当前值阈值判断趋势：低于0.4为下降、达到0.7为改善，否则稳定。

**影响：** 这不能回答“比上次是否改善”。本次该学生经过正确复习确有提升，所以不能仅凭此样本认定方向恰好错误；但返回的 previous 并非上次值，趋势实现也无法区分持续高分和高位下降。

定位：[mistake/service.go](../../../backend/internal/application/mistake/service.go) 中 `Previous/Current` 赋值及 `masteryTrend`。

**优化与验收：** 保存带时间戳的前后测量或依据作答事件重建变化，将“当前水平”与“趋势”分开。至少覆盖低水平上升、高水平下降、基本不变、缺乏历史四种情况；缺乏历史时展示未知。

证据：[followup-evidence.json](../../../output/student-feedback-audit-1017/followup-evidence.json) 中 `method-mistakes-after-reviews`。
