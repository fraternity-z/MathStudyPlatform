# 作答证据与有效学习时长

本规则由 `0033_exercise_evidence_integrity` 和对应前后端版本共同交付，修复重复题、异常时长、提示交付及过程评价缺口。2026-10-17 的闭环修复复用既有字段，无新增数据库迁移。

## 作答次数与掌握证据

所有正式提交继续保存最终答案得分、实际练习次数和不可变题目快照。提交在学生学习状态事务锁内检查全部历史：同题 ID 或忽略大小写、Unicode 空白后题面完全一致的已提交记录均视为既有暴露，不受近 30 天读取窗口限制。

明确给出算术函数、要求数值点一阶导数的题目另使用保守结构签名，统一函数名、单变量名和常见求导表述；例如 `f(x)=(2x+1)^2` 求 `f'(0)` 与 `g(t)=(2t+1)^2` 求 `g'(0)` 视为同题。系数、表达式或求值点变化仍可作为新题；附加条件、不同目标和无法可靠识别的形式回退到题面匹配，不用向量或模糊文本相似度决定掌握权重。提交、近期反馈与生成避重复共用该签名，范围有限，不宣称具备通用数学语义等价能力。

| 场景 | `evidence_kind` | 掌握度权重 |
| --- | --- | --- |
| 无既有暴露的首次作答 | `first_attempt` | 1 |
| 普通同题重做、换 ID 的相同题面、提前复习、历史错题重做、每日题即时订正 | `repeat_practice` | 0 |
| 携带有效任务与 revision 的到期复习 | `scheduled_review` | 1 |
| 已记录题目提示 | 保留上述来源 | 权重上限 0.35 |

零权重记录不会更新 DKT 概率、置信度、最后测量时间、交互序列或画像行动的有效计数；实际作答量和最终答案正确率仍记录。原有画像行动基于 DKT 尝试次数的基线保持不变，新进度只累计被接纳的掌握测量，辅助测量可以计入行动，但不能解释为未求助的新题验证。反馈中的有效新题数继续单列，并排除重复、提示辅助和过程证据不足的正确作答。

提交幂等键及响应快照仍覆盖全部事务。相同 key 重放不会再次消费计时或记录证据；不同 key 的同题提交由同一学生锁串行判定暴露。到期复习沿用 revision 校验，不能通过不断更换 key 连续推进复习。

## 学习时长

前端进入可作答的题目时调用 `POST /api/v1/exercise/start`，携带与正式提交一致的题目、每日题或错题任务上下文。服务端重新校验权限和任务 revision 后登记时钟。同一学生、同题未消费的时钟重复开始保持幂等，两小时后过期；学生开始其他题目时清理本人过期时钟。

前端只在练习页面启用、窗口可见且获得焦点时累计时间，切后台、离开页面、切换练习模式及提交判题期间暂停。计时采用单调时钟，换题或切换任务上下文重置，重试保留原提交载荷。

正式提交只接受整数 `time_spent_seconds`，范围为 0–7200，超界返回 `400 INVALID_STUDY_TIME`；JSON 非整数或溢出由严格解码拒绝。事务内有效时长取客户端报告和服务端可验证区间的较小值：区间开始为题目开始时间与该学生最近一次提交时间的较晚者，结束为本次请求进入应用层的时间。模型处理耗时不计入，多端或多题重叠区间不重复累计；跨上海自然日不重置单题上限。

没有开始记录、计时服务不可用、时钟过期或区间倒置时，作答仍可评分，但有效时长为零。服务器只能界定耗时上界，无法证明学生始终在学习；前端可见性也不是防作弊认证。

`content_attempts.time_spent_seconds` 保存有效时长，`reported_time_spent_seconds` 保存原报告，统计、画像和班级均值继续聚合有效列。迁移仅将历史负数及超过 7200 秒的明显异常置零，原值留存审计；范围内旧数据仍保留，不追认其经过服务器验证。

## 提示交付

普通题目详情的 `hints` 保留为空数组以兼容旧客户端，通过 `hints_available` 表示是否有提示。显式求助复用练习 Tutor；第一段非空内容交付前持久化提示证据，失败不交付正文，普通加载和仅建立计时不算求助。提示证据与提交共用学生锁，提交后状态冻结。

班级题与 AI 题统一使用绑定题目的辅导入口，仍由练习模块逐轮校验题目访问权限。旧 `/session/new?exercise_id=…` 链接也转到绑定会话。返回练习依据服务端题目来源恢复班级/AI 模式；两种模式的答案、步骤及重试上下文保留在当前学生的内存 Provider 中，刷新、登出或换学生时清空。普通无题目绑定的聊天不能可靠归因，不追认其提示状态。

## 过程评价

最终答案的 `is_correct/score/evaluation` 契约保持不变。提供非空 `answer_steps` 时，复用 Math Solver 的独立验证能力，以步骤模式检查方法、条件、推理和计算；不得仅凭最终选项判定过程。过程评价与作答同事务保存在 `process_evaluation`，并进入幂等响应。

| 过程状态 | 行为 |
| --- | --- |
| `not_provided` | 未写步骤，不判过程错误，不影响原本的答案评分体验 |
| `correct` | 步骤有充分依据且成立；最终答案错误时保留错误得分，但掌握扣减权重上限为 0.35 |
| `incorrect` | 保存过程诊断并纳入错题与复习；最终答案正确时保留得分、权重为零，重置纠错计划 |
| `indeterminate` | 步骤不足、低置信度、模型不可用或结果无效；保留最终答案评分，正确答案暂不增加掌握度或推进复习成功阶段 |

过程错误即使最终答案正确，也进入错题列表、详情、错误次数与复习任务，归档和精确重做使用同一判定。明确错误重置为 1 天纠错计划；仅过程证据不足则记录复习、更新 revision 并保留解析访问，成功阶段保持不变，24 小时后重新验证，不直接判定学生不会。模型调用在事务外，步骤验证最多使用 30 秒且受父请求截止时间约束，超时保留最终评分并降级过程为不确定；父请求取消仍中止写入。每次最多 20 条步骤，每条最多 5000 字节。历史过程状态不补造，也不使用当前模型重判旧作答。

标准练习面板提供可选关键步骤输入，每行一条，提交前去空白。空步骤不增加模型调用；最终答案结果、过程结论及证据分别展示。相同步骤的提交重试复用幂等键，编辑步骤后使用新键；已记录提交锁定输入。

## 画像、路径与趋势

画像从最近 30 天作答冻结的知识点补充最多 6 个近期概念，不再只依赖 DKT 状态。明确过程错误优先进入纠错建议和可执行行动，即使它的掌握权重为零；没有有效测量时返回 `mastery: null` 并显示“待验证”。近期错误优先于保持复测状态，不虚构低掌握度。文字画像读取同一证据。

学习路径的完成与先修解锁同时要求原掌握度/置信度阈值和反馈的 `transfer` 阶段：至少 5 道不同独立新题、最近 5 道至少 4 道正确、至少 2 道正确发生在首份独立证据 24 小时后。高 DKT 数值、重复作答或同日连续答对本身不代表完成；新错误会恢复纠错状态。

错题及复习列表的 `mastery.previous` 来自该知识点最近两次正权重提交响应中的实际 `mastery_update`，与当前测量值比较，差值超过 0.01 才标记上升或下降。多知识点按同一集合取均值；任一知识点缺少两次有效记录，返回 `previous: null, trend: unknown`，不使用当前高低水平猜趋势。历史缺失的快照不补造。

## 生成与异常恢复

独立求解和验证只在结构解析失败时额外重试一次，沿用原请求截止时间；网络错误、取消及有效的数学错误结论不在该层重试。题目生成、独立求解、步骤验证分别记录固定阶段、耗时和结果类别，日志不包含模型正文、学生文本或凭据。验证失败仍拒绝保存题目。前端明确显示正在生成并独立验算，允许取消；取消立即停止等待，迟到结果不能替换当前题目。

## 部署与回退

先排空旧 API 写入、备份、运行迁移，再部署配套 API 和前端。旧客户端可以继续作答，但未建立服务器时钟的记录计零时长。不得让旧 API 与新 API 混跑，否则旧链路仍可能写入未经新证据政策筛选的掌握数据。

迁移不自动重算历史 DKT、置信度或历史画像。既有高掌握度需通过后续新题测量或单独审计的历史重放进行校准，不应把修复上线解释为旧状态已校准。回退应停止写入并恢复匹配备份；旧应用会将零权重误归一为全权重，不能直接使用新数据库恢复旧写入链路。
